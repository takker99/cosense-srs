# 学習理論とアルゴリズム背景

このドキュメントは cosense-srs の設計判断を既存
SRS・記憶研究の知見と結び付ける。実装計画と同時に“なぜそうするか”を明確化する。

## 1. 主要アルゴリズム比較

| モデル           | 中心パラメータ                                                | 特徴                                   | 弱点                                   | 本プロジェクトでの扱い             |
| ---------------- | ------------------------------------------------------------- | -------------------------------------- | -------------------------------------- | ---------------------------------- |
| Leitner Box      | 箱インデックス                                                | シンプル、説明容易                     | 粒度粗い / 個別適応不可                | 学習導入時チュートリアル的参考のみ |
| SM-2 (Anki 初期) | ease factor, interval                                         | 実装簡易、広く普及                     | 停滞 (ease ドリフト), 遅延影響扱い弱い | 過去データ移行互換視点で参照       |
| FSRS             | stability, difficulty, retrievability, elapsed/scheduled days | 回答時刻と忘却確率モデル化、最適化可能 | パラメータ推定が複雑                   | メインモデル (ts-fsrs)             |
| FSRS-4/改良案    | 強化学習/微調整                                               | ユーザ固有最適化                       | 実装コスト高                           | 将来の研究余地                     |

## 2. 忘却曲線と最適化

Ebbinghaus 型を前提とし、FSRS では _stability_
が保持期間を規定し、retrievability R(t) は `R = exp(-t / stability)`
近似で表現される (実際の FSRS 実装は近似関数)。 目標保持率 (Target Retention) を
`RT` とすると、次回間隔 `I` は `I = - stability * ln(RT)` 付近が候補。

### 目標保持率の可変化

- 初期: 0.9 (90%)
- カード難度分布 / ユーザ時間制約に応じ 0.85~0.95 を調整
- 実測正答率が期待より高い: RT を上げる or new 上限増やす

## 3. パラメータ推定戦略

| 戦略                 | 説明                 | 長所             | 短所                    |
| -------------------- | -------------------- | ---------------- | ----------------------- |
| 一括最尤 (Batch MLE) | 期間毎に全ログ再学習 | 精度高い         | O(N) フルスキャンコスト |
| 増分更新 (Online)    | セッション後差分更新 | リアルタイム適応 | 実装複雑 / 収束不安定   |
| Bayesian (MCMC/VI)   | 事前分布 + 尤度      | 不確実性扱い     | 計算資源高              |

短期計画ではバッチ最尤 (小規模データで十分高速) →
ログ肥大後はインクリメンタルへ移行。

## 4. 応答時間の活用

- 回答正誤 + レーティングのみでは潜在難易度再推定が遅い。
- キー入力までのラグを `t_answer` として収集し、閾値 (例: 2.0s) との比で補正:
  - 速く正答: 難易度微減 / stability 微増
  - 遅く正答: レーティング Good でも Hard に近い扱い
- 初回導入カードでの迅速な識別に有効。

## 5. Leech (反復失敗) 処理

- 規則例: `lapses >= 8` かつ `stability < s_min` でフラグ
- 対応: (A) 自動サスペンド (B) Cloze 分割提案 (C) メモの再編集誘導
- メトリクス: leech 率上昇は教材品質 or 過剰導入のシグナル

## 6. Sibling Bury (同一 Note 内 Cloze)

- 同時学習で文脈依存答え当てが発生し真の回想力測定が歪む。
- 戦略: セッション内で 1 Cloze 出題後、同一 note の他 Cloze
  を一時保留キューへ。日跨ぎ bury は負荷次第で可変。

## 7. Backlog 負荷平準化

- 長期未学習カードが一度に due になるスパイクを避ける。
- 予測: 未来 30 日の due 分布を計算し、特定日ピークが閾値超過なら新規導入削減 or
  interval fuzz 増幅。

## 8. Interval Fuzz

- 同一日・類似安定度のカードが集中しないよう ±(5~10%) 乱数。
- 冪等性確保: `hash(cardId + dueEpochDay)` を擬似乱数種にして deterministic
  fuzz。

## 9. 新規カード導入管理

| ポリシー            | 意図                                             |
| ------------------- | ------------------------------------------------ |
| 1 日あたり new 上限 | 過学習防止 / 未来負荷平準化                      |
| 上限動的調整        | 実働時間, 前日残タスク, Retention 過剰高時に増加 |

## 10. モデル再推定トリガ

- 最低ログ件数 (例 300 件) 到達
- 正答率 vs 期待保持率 差分 > 5% が 3 日継続
- 安定度分布が片側 10% 外に偏位

## 11. 忘却遅延ペナルティ

- 予定日より `d` 日遅れ: 有効経過日数 `elapsed_days += d * penalty_factor` (例
  0.5) として再計算
- 強制的リセットより滑らかな調整

## 12. Cloze 番号欠番扱い

- 現状: 欠番無視
- 仕様確定: 欠番許容し、存在する番号だけカード化。GUID
  変化時の再マッピング注意。

## 13. 統計的監視 (Monitoring)

| 指標               | 意味                   | 異常閾値例         |
| ------------------ | ---------------------- | ------------------ |
| Retention Gap      | 期待保持率 - 実測正答  | >10% 継続 3 日     |
| Lapse Rate         | lapses / review reps   | >0.25              |
| Ease Drift         | 平均 difficulty 変化率 | 1 週間で ±0.1 以上 |
| Load Forecast Peak | 30 日内最大 / 平均     | >2.5               |
