# 未実装・不完全な部分 (詳細版)

設計上/運用上のギャップをカテゴリ別に整理。優先度は暫定
(★★★★☆=高)。詳細なアルゴリズムや背景理論は関連ドキュメントに委譲する。

---
## 1. 学習ロジック / スケジューラ

### 1-1. 個別ギャップ一覧
| 項目 | 現状 | 改善方向 / 目標 | 優先度 |
|------|------|-----------------|---------|
| メモリ内状態更新 | 回答後 DB だけ更新し Map 未更新 | `cardsInThePage` など in-memory エンティティ差し替え + 直後の優先度再計算 | ★★★★☆ |
| 出題キュー構造 | 単一配列シャッフル | Learning / Review(期限到来) / New(backlog) 分離 + 優先度(Next Due / Stability) キュー | ★★★★☆ |
| Learning steps | 未実装 | 1分 / 10分 等の短期再出題 (可変ステップ) | ★★★★☆ |
| Sibling bury | なし | 同一 Note / Cloze 兄弟を同日連続出題しない (間隔挿入) | ★★☆☆☆ |
| Backlog 平準化 | 期限超過カード未考慮 (一括突入) | 日毎上限 + f(過重度) による段階放出 | ★★★☆☆ |
| Due fuzz (平準化) | なし | 確率的/決定的 fuzz で山谷平滑化 | ★★☆☆☆ |
| Leech 処理 | なし | 一定 lapse 回数でサスペンド + タグ/統計反映 | ★★☆☆☆ |
| Retention 目標 | 不明示 (デフォルトFSRS任せ) | 90~95% 目標を推定し自動調整 | ★★★☆☆ |
| 難易度分布補正 | 偏り検出なし | Difficulty ヒストグラム監視→再正規化/調整 | ★★☆☆☆ |

### 1-2. 実装方針メモ
* In-memory: 回答イベントで FSRS.next 結果を即座に適用し、学習中カード再挿入 (learning step) / キュー再構築。
* 優先度: (1) 期限超過 (overdue ratio 高) (2) 今日 due (3) learning step 再出題 (4) 新規導入 の順で複合スコア。
* バックログ: 過去未処理数 N を N/days_spread で均等配分し上限制御。
* Fuzz: 安定性由来の期待復習間隔 ± p% (決定的シード) で平準化。
* Hook API: スケジューラ内部イベント (onAnswer, onQueueRebuild) を将来 metrics に publish。

詳細なギャップ優先度分析は [srs_design_gaps.md](./srs_design_gaps.md) 参照。

## 7. セキュリティ / 信頼性 (SecOps)
* 認可: 他ユーザ table への越境書き込み防止 (サーバ側検証前提、クライアント側も prefix チェック)。
* 入力サニタイズ: Scrapbox 解析結果 (HTML) の XSS 防御。Shadow DOM で部分軽減だが追加 sanitize 必要性評価。
* コンフィグ秘匿: 将来的な API Key (翻訳等) の管理方針未定。
* 監査ログ: 重要操作 (import/export, parameter update) を匿名メトリクス化。
